# Railway Booking System
### Система бронирования железнодорожных билетов

Консольная информационная система на Java для управления пассажирами
и бронированием железнодорожных билетов. Данные хранятся в PostgreSQL,
доступ осуществляется через JDBC. Проект реализован по многослойной
архитектуре (Console UI → Service → Repository → Database).

## Предметная область

Система предназначена для автоматизации процесса **бронирования
железнодорожных билетов**. Пассажиры могут оформлять брони на поезда
с указанием маршрута, даты, вагона и места; система контролирует
занятость мест, корректность данных и допустимые переходы статусов
бронирования.

**Основные участники и объекты:**
- **Пассажир** — участник предметной области.
- **Бронирование** — основная сущность системы.

## Сущности

### 1. Passenger (Пассажир)

| Поле             | Тип          | Ограничения         | Описание                  |
|------------------|--------------|---------------------|---------------------------|
| `id`             | BIGSERIAL    | PK                  | Идентификатор             |
| `full_name`      | VARCHAR(150) | NOT NULL            | ФИО пассажира             |
| `passport_number`| VARCHAR(20)  | NOT NULL, UNIQUE    | Номер паспорта            |
| `email`          | VARCHAR(100) | NOT NULL, UNIQUE    | Email                     |
| `phone`          | VARCHAR(20)  | NOT NULL            | Телефон                   |
| `birth_date`     | DATE         | NOT NULL, CHECK     | Дата рождения             |

### 2. Booking (Бронирование)

| Поле             | Тип           | Ограничения                  | Описание                     |
|------------------|---------------|------------------------------|------------------------------|
| `id`             | BIGSERIAL     | PK                           | Идентификатор                |
| `passenger_id`   | BIGINT        | FK → passengers.id, NOT NULL | Пассажир                     |
| `train_number`   | VARCHAR(10)   | NOT NULL                     | Номер поезда                 |
| `route_from`     | VARCHAR(100)  | NOT NULL                     | Станция отправления          |
| `route_to`       | VARCHAR(100)  | NOT NULL                     | Станция назначения           |
| `departure_date` | DATE          | NOT NULL                     | Дата отправления             |
| `departure_time` | TIME          | NOT NULL                     | Время отправления            |
| `wagon_number`   | INT           | NOT NULL, CHECK ≥ 1          | Номер вагона                 |
| `seat_number`    | INT           | NOT NULL, CHECK ≥ 1          | Номер места                  |
| `price`          | NUMERIC(10,2) | NOT NULL, CHECK > 0          | Стоимость билета             |
| `status`         | VARCHAR(20)   | NOT NULL, CHECK              | Статус брони                 |
| `created_at`     | TIMESTAMP     | NOT NULL, DEFAULT NOW()      | Дата создания                |

### 3. BookingStatus (enum)

| Значение     | Описание                          |
|--------------|-----------------------------------|
| `CREATED`    | Бронь создана                     |
| `CONFIRMED`  | Бронь подтверждена                |
| `PAID`       | Билет оплачен                     |
| `COMPLETED`  | Поездка завершена                 |
| `CANCELLED`  | Бронь отменена                    |

**Связь:** один пассажир → много бронирований (**1:M**).

## Бизнес-правила

Все правила реализованы в слое `service`.

| № | Правило                                                                                          |
|---|--------------------------------------------------------------------------------------------------|
| 1 | Нельзя создать бронирование без существующего пассажира (`passenger_id` обязателен и валиден)    |
| 2 | Нельзя забронировать место, которое уже занято на этом поезде, вагоне и дату                     |
| 3 | Номер вагона и места должны быть ≥ 1                                                             |
| 4 | Дата отправления не может быть в прошлом                                                         |
| 5 | Цена билета должна быть > 0                                                                      |
| 6 | Запрещены недопустимые переходы статусов: из `CANCELLED` нельзя никуда; `PAID` — только из `CONFIRMED` |

При нарушении правил выбрасывается `BusinessException` с понятным сообщением.
